# Start from a networking goal

Use the user's request and existing project context to establish the following.
Ask only for missing details that materially change whom to find or how to contact
them. Discovery and preparation can proceed before any invitation is authorised.

- **Purpose:** exchange ideas, find collaborators, learn from practitioners, explore
  career opportunities, reconnect, or build a professional community.
- **Relevant people:** topics, roles, work, communities, events, and professional
  context that make a connection useful. Apply location or language preferences only
  when relevant and supplied. Avoid ranking by fame or follower count by default.
- **Starting evidence:** names, public articles/projects, conference programmes,
  open-source contributors, permitted exports, existing contacts, or a roster.
- **Relationship context:** known personally, met at an event, introduction available,
  shared community, or new contact. Record unknown when it is unknown.
- **Contact preferences:** intended account/channel, note or no note, tone, exclusions,
  and which concrete actions the user has authorised.

Store these as a short private `network-plan.md` in the project. This is agent-readable
context, not a configuration parser. Do not duplicate personal data into the skill.
Use an existing canonical contact tracker when available. With no existing tracker,
the private Reconnect ledger can be the project's canonical invitation-state store.

## Useful starting patterns

| Request | Discovery starting point | Evidence of relevance |
| --- | --- | --- |
| Find people doing related research | Papers, labs, public talks, project pages | Specific work intersects the user's question |
| Meet peers in a professional field | Public professional communities, projects, events | Relevant practice and an actual topic to discuss |
| Follow up after a conference | Public programme plus the user's meeting notes | Distinguish confirmed encounters from merely attending |
| Reconnect with former colleagues | Permitted contact list, public employment history | Identity and dates align |
| Find potential mentors | Public teaching, talks, or relevant professional experience | A specific learning goal; never assume willingness |
| Grow a community | Its stated purpose and existing member referrals | Appropriate professional interest or participation |

Each suggested person should have a name, profile, concise reason they fit, evidence
source, relationship context, and uncertainty. Lead with people the user could have
a meaningful exchange with. A LinkedIn URL alone is insufficient justification.

Do not turn a request to expand a professional network into indiscriminate lead
collection. If the proposed audience is vague, produce a small illustrative shortlist
to clarify fit before enlarging discovery. A shortlist does not authorise contact.

## Invitations and ongoing relationships

When requested, prepare concise invitations using the actual reason to connect.
For new contacts, shared interest can be enough; do not fabricate shared history.
Respect a no-note preference. Treat acceptance as a connection, not consent to an
unrelated sales sequence. Follow-up messages, introductions, group invitations,
and reminders each follow the scope the user actually requested.

At a review point, explain who was found, why they fit, what is unresolved, and what
actions were observed. Use outcomes to refine the audience without automatically
expanding it or increasing the contact volume.
